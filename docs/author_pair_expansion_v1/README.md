## Use the packages

Open the local master instructions:

`research_runs/author_pair_expansion_v1/release_v1/START_HERE.md`

Start with `existing_collection`, then `new_collection`. Each package has a
`BATCH_INDEX.json`, `common/` attachments, per-batch `paragraphs.jsonl` and `TASK.md`,
selection/provenance keys, a coverage report and input/output hashes.
The batch index specifies the response destination. The two packages have
separate response namespaces, so identically numbered files cannot collide.

Use the established manual GPT-6 workflow and request High thinking effort.
Record actual visible settings and conversation arrangement; separate chats do
not establish independence or disabled memory. No API credential or GPU is needed.
Keep first responses; corrections require separately versioned files.

The shared output specification is the existing `human_prose_annotation_v1`
schema with the lossless compact view of the 132-item provisional taxonomy.
It requests neutral plain English, original text copied exactly, actors, claims,
conditions, quantities, negation, modality, causal relationships, evidence quotes,
source and target rhetorical schemas, finite claim-bound transformations, and
uncertainty flags. Both texts use the same schema. Annotation is joint, not
independent or verified author intent. Originals and extraction provenance stay private.

## Selection and boundaries

New paper roles are declared before annotation responses. Existing six-paper
neutral-reconstruction training-side commitments remain training-side. For each
non-Fama group, eight previously unassigned papers are training-side, two are
development-side and two remain deferred. Every new group contributes five
training-side and two development-side paper assignments. Actual paragraph counts
can be smaller. These are author-specific whole-paper development partitions,
not a replacement for the older pooled author-held-out task.

The 45 Fama and 20 pooled-author reserved examples remain sealed. No reserved
paragraph bodies are used. Deferred works are not certified fresh confirmation
data; earlier external chat exposure remains unobservable.

Selection uses existing curation candidates only, 70–260 words, no known hold,
no known duplicate, and no unresolved context or table/equation-reference flag.
OCR still carries its explicit lack of independent verification. It favors
different pages and moderate lengths, never detector scores or an authorship
classifier. The four post-annotation holds and all twelve previous
neutral-reconstruction source paragraphs are excluded. Exact/near source overlap
is checked against nonreserved Fama and teacher targets, prior sources and the
other package using five-word shingles with a 0.80 Jaccard threshold. This cannot
exclude all paraphrased overlap; admission still needs semantic checks.

The old 39-paper extraction is unchanged. For the 28 new works, all **929 pages**
were extracted; **461 pages** used CPU-only macOS Vision OCR. The initial sandbox
attempt failed before writing OCR pages; retry logs are retained. Follow-up found
supplementary private-use characters in a native font layer and added OCR. The
new versioned screen holds private-use characters in all Unicode planes, not just
the BMP. Historical v1 screening retains its original behavior; earlier datasets
were not regenerated by that code change.

The final curation snapshot contains 569 candidates and 6,085 held blocks, with

This is extraction accounting, not transcription accuracy. All candidates remain

## After responses return

First check complete unique IDs, unchanged originals and hashes, schema validity,
quote occurrences, sentence coverage, taxonomy IDs, claim/entity/relation links,
transformation direction, quantities and operators. Quarantine incomplete,
context-dependent or disputed alignment. Mechanical validity and a generator's
self-check do not prove semantic equivalence. Compare claim preservation, copying
and actual style contrast before admitting a versioned paired release. Never
reassign a development paper after seeing its quality or detector scores.

No annotation responses, fine-tuning, inference experiment, classifier fit or
detector measurements were generated in this release. The earlier mixed research
findings and limits on Fama-style claims still apply.

## Reproduction

Use a fresh output directory and the private metadata/source files:

```sh
python3 scripts/data/acquire_author_papers.py --help
python3 scripts/data/freeze_author_inventory_v3.py --help
PYTHONPATH=src python3 -m fama_style.research.author_curation \
  --extraction research_runs/author_curation_v2 \
  --output /tmp/author_curation_reproduction \
  --inventory docs/author_inventory_v3/inventory.json \
  --expected-papers 28 --protocol author_curation_v2_1
PYTHONPATH=src python3 -m fama_style.research.author_pair_expansion --help
```

Private role plans and manifests record the exact inputs. The exact executed
curation source is also retained under the release's `reproducibility/` directory
with the original manifest's code hash. The final curation pass reproduced
byte-for-byte from frozen extraction, including its manifest. Synthetic CPU tests
check role protection, duplicate exclusion, conservative holds, preservation of
originals, supplementary font corruption, untouched reserved files and deterministic
package contents. No model weights or GPU are needed. Fresh OCR may vary with OS;
curation from frozen extraction and package rebuilding are deterministic.
